# ADR-0001: Изоляция движка доски в entities/board и дискретная сетка чанков

* **Статус:** Принято
* **Контекст:** Развивается MVP веб-доски `Kinsorboard` на React, TypeScript, Vite и SCSS с соблюдением Feature-Sliced Design (FSD). Нужен предсказуемый холст без тяжёлых сторонних графовых движков и с понятными границами рабочего поля.

## Решение

1. Вся логика рендеринга, камеры, геометрии, инструментов и взаимодействия с `<canvas>` инкапсулируется с слайсе `src/entities/board` (`BoardEngine`, `ViewportCamera`, `BoardRenderer`, `geometry.ts`, `tools.ts`).

2. Виджеты (`Topbar`, `Toolbar`, `CanvasSizePanel`, `Navigator`, `BottomBar`) и `BoardPage` взаимодействуют с движком через публичный API слайса и подписку `subscribe(...)`, без смешивания canvas-логики с UI-компонентами.

3. Рабочая область задаётся дискретной сеткой чанков (`100`, `200`, `400` чанков) с ограничением координат объектов и области рисования границами мира.

## Последствия

- **Плюсы:** Проще тестировать и развивать движок независимо от интерфейса; `steiger` и границы слоёв FSD остаются прозрачными; Отсутствует лишний поллинг по таймеру.
- **Минусы / компромиссы:** При проявлении новых типов объектов или режимов нужно обновлять несколько модулей внутри `entities/board` и следить за их публичным экспортом.
