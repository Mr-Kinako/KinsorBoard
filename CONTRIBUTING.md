# Contributing & Engineering Guidelines

Этот документ фиксирует архитектурные соглашения, правила работы с кодом, версионирование и стандарты Git для **Kinsorboard**.

---

## 1. Архитектура и структура (FSD)

Проект строится по **Feature-Sliced Design (FSD)** с автоматическим контролем границ слоёв через **Steiger**:

- `src/app/` — инициализация приложения, роутинг (`react-router`), глобальные стили (`styles/global.scss`) и лейауты (`layouts/`).
- `src/pages/` — страницы приложения (`pages/board/`).
- `src/widgets/` — самостоятельные композиционные блоки UI (`topbar/`, `toolbar/`, `navigator/`, `canvas-settings/`, `status-bar/`).
- `src/features/` — пользовательские сценарии и действия.
- `src/entities/` — бизнес-сущности и доменная логика (`entities/board/`).
- `src/shared/` — переиспользуемые ресурсы и дизайн-токены (`shared/styles/_variables.scss`, `shared/lib/`, `shared/ui/`).

### Правила изоляции слоёв:
1. **Изоляция Canvas Engine:** Весь низкоуровневый рендеринг, камера (`ViewportCamera`), математика геометрии и управление инструментами живут в `src/entities/board/lib/` на чистом TypeScript. Движок не должен зависеть от React и его жизненного цикла.
2. **Обязательные сегменты слайсов:** Все слайсы в `pages`, `widgets`, `features`, `entities` структурируются по стандартным FSD-сегментам (`ui/`, `model/`, `lib/`, `api/`) в соответствии с правилом `fsd/no-segmentless-slices`.
3. **Строго целевые реэкспорты (`index.ts`):** В публичный API слайса (`index.ts`) экспортируются **только** те типы, функции и компоненты, которые реально импортируются вышестоящими слоями в текущий момент. Запрещено делать реэкспорты «на вырост» и корневые `index.ts` на уровне слоёв (`fsd/no-layer-public-api`).

## 2. TypeScript и качество кода

- **Strict Mode:** Включён `strict: true`. Использование `any` запрещено.
- **Типизация событий и геометрии:** Координаты, ограничивающие рамки (`BoundingBox`), конфигурации чанков и инструменты описаны строгими интерфейсами и union-типами.
- **Линтинг и форматирование:**
  - Перед коммитом код обязан проходить `npm run checks` (`prettier --check .`, `steiger ./src`, `eslint .`) без ошибок и предупреждений (включая `react-hooks/exhaustive-deps` — не подавлять правила через `eslint-disable`).
  - Форматирование контролируется Prettier и `.editorconfig`.
- **Стилизация (SCSS):**
  - Используются SCSS-модули (`*.module.scss`) и глобально инъектируемые через Vite переменные из `src/shared/styles/_variables.scss` (повторный `@use` переменных в модулях запрещён во избежание циклов).
  - Цветовая палитра выдерживается в спокойных, приглушённыx тёмных и лавандовых тонах без кислотных акцентов.

## 3. Версионирование (SemVer)

Используется формат **`MAJOR.MINOR.PATCH-PRERELEASE`** (текущий этап: `0.1.0-alpha.x`):

- На этапе пре-релиза (`0.1.0-alpha.x`) до выпуска стабильной `0.1.0` при добавлении итераций инкрементируется номер канала пре-релиза (`alpha.0` -> `alpha.1` -> `alpha.2`).
- `PATCH` (`0.1.1`) поднимается только для мелких правок и багфиксов уже выпущенной версии.
- `MINOR` (`0.2.0`) поднимается при завершении крупного этапа нового функционала.

## 4. Стандарт коммитов (Conventional Commits)

Все коммиты пишутся строго на **английском языке** в повелительном наклонении (imperative mood), с обязательным `<scope>`, с маленькой буквы и без точки в конце:

```text
<type>(<scope>): <short description>
```

### Допустимые типы (`type`):
- `feat` — новая пользовательская функциональность (`feat(canvas): add select, drag and text tools`)
- `fix` — исправление бага (`fix(board): prevent canvas pan drift and fix viewport layout`)
- `refactor` — изменение структуры или кода без изменения поведения (`refactor(board): split engine into camera, geometry and renderer`)
- `docs` — изменения в документации (`docs(repo): update guidelines and add project structure`)
- `style` — правки форматирования, отступов, SCSS без изменения логики (`style(toolbar): adjust active button contrast`)
- `chore` — обновление конфигов, зависимостей, рутина (`chore(lint): configure steiger FSD rules`)
