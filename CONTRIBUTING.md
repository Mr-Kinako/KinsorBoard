# Contributing & Engineering Guidelines

Этот документ фиксирует архитектурные соглашения, правила работы с кодом, версионирование и стандарты Git для **Kinsorboard**.

---

## 1. Архитектура и структура (FSD)

Проект строится по упрощённой и прагматичной **Feature-Sliced Design (FSD)** без лишней вложенности:

- `src/app/` — инициализация приложения, роутинг (`react-router`), глобальные стили и лейауты.
- `src/pages/` — страницы приложения (`BoardPage.tsx` и др.).
- `src/widgets/` — самостоятельные композиционные блоки UI (`topbar/`, `toolbar/`, `navigator/`, `canvas-settings/`, `status-bar/`).
- `src/features/` — пользовательские сценарии и действия.
- `src/entities/` — бизнес-сущности и модели данных (`board/`).
- `src/shared/` — переиспользуемые утилиты и изолированный движок рендеринга (`lib/canvas/`, `ui/`).

### Правила изоляции слоёв:
1. **Изоляция Canvas Engine:** Весь низкоуровневый рендеринг, математика координат (`screenToWorld`), управление зумом и сеткой чанков живут в `src/shared/lib/canvas/` на чистом TypeScript. Движок не должен зависеть от React и его жизненного цикла.
2. **Строго целевые реэкспорты (`index.ts`):** В публичный API модуля (`index.ts`) экспортируются **только** те типы, функции и компоненты, которые реально импортируются другими слоями в текущий момент. Запрещено делать реэкспорты «на вырост».
3. **Плоская организация внутри слайсов:** Не создавать лишние подпапки (`ui/`, `model/`), если в модуле 1–3 файла.

## 2. TypeScript и качество кода

- **Strict Mode:** Включён `strict: true`. Использование `any` запрещено.
- **Типизация событий и геометрии:** Координаты, векторы, конфигурации чанков и инструменты описаны строгими интерфейсами и union-типами.
- **Линтинг и форматирование:**
  - Код обязан проходить проверки ESLint без ворнингов (включая `react-hooks/exhaustive-deps` — не подавлять правила через `eslint-disable` без крайней архитектурной необходимости).
  - Форматирование контролируется Prettier и `.editorconfig`.
- **Стилизация (SCSS):**
  - Используются SCSS-модули (`*.module.scss`) и общие переменные из `src/app/styles/_variables.scss`.
  - Цветовая палитра выдерживается в спокойных, приглушённых тёмных и лавандовых тонах без кислотных акцентов.

## 3. Версионирование (SemVer)

Используется формат **`MAJOR.MINOR.PATCH-PRERELEASE`** (текущий этап: `0.1.0-alpha.x`):

- На этапе пре-релиза (`0.1.0-alpha.x`) до выпуска стабильной `0.1.0` при добавлении итераций инкрементируется номер канала пре-релиза (`alpha.0` -> `alpha.1` -> `alpha.2`).
- `PATCH` (`0.1.1`) поднимается только для багфиксов уже выпущенной версии.
- `MINOR` (`0.2.0`) поднимается при завершении крупного этапа нового функционала.

## 4. Стандарт коммитов (Conventional Commits)

Все коммиты пишутся строго на **английском языке** в повелительном наклонении (imperative mood), с маленькой буквы и без точки в конце:

```text
<type>(<scope>): <short description>
```

### Допустимые типы (`type`):
- `feat` — новая пользовательская функциональность (`feat(canvas): add rectangle and pen drawing tools`)
- `fix` — исправление бага (`fix(canvas): prevent zoom drift on window resize`)
- `refactor` — изменение структуры или кода без изменения поведения (`refactor(board): remove unused type re-exports`)
- `docs` — изменения в документации (`docs(contributing): add project engineering guidelines`)
- `style` — правки форматирования, отступов, SCSS без изменения логики (`style(toolbar): adjust active button contrast`)
- `chore` — обновление конфигов, зависимостей, рутина (`chore(deps): update eslint configuration`)
